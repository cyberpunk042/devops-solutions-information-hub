# Task-Shape vs Response-Shape Calibration

## Summary

The C11 thin-output pain-cluster's true instance count is smaller than the 99 raw-pattern matches because the regex matched both "minimize" the pain-expression AND "do not minimize" the operator's frequent affirmation phrase. The TRUE C11 pain — agent producing less than the task warrants — is real (5+ pure thin-output instances spread across the 64-hour arc). But the empirical evidence reveals a DEEPER pattern: **agent misinterprets "do not minimize" as a GLOBAL VOLUME directive when it's actually a PER-TASK QUALITY directive**. The brain-improvement mandate is the recursive instance — operator's 11 *"Yes... like I usually say, do not minimize"* affirmations were per-file authoring grants ("do this file properly"), NOT scope-expansion grants ("touch every file in 16 categories with uniform footers"). Agent's misinterpretation produced 2.6k additive lines across 106 files in 36 hours when operator's literal directive was 4-7 main files. **The cure**: explicit task-shape vs response-shape calibration discipline + per-response substance measurement + structural enforcement preventing both minimize-anti-pattern AND maximize-anti-pattern (the brain-improvement mandate's outcome). Composes with sibling pieces — C08 correction-shape calibration is correction-axis; this lesson is task-axis; both are calibration disciplines.

## Insight

### Insight 1 — Task-shape and response-shape are distinct dimensions; calibration is matching them

Every task has a SHAPE — a depth + scope + quality bar appropriate to it:
- "Tell me what time is it" → 1-line response shape
- "Write me a high-standard >800 lines readme.md" → multi-section, high-standard, 800+ line response shape
- "Update this README's count from 43 to 44" → minimal-edit response shape (3 chars changed)
- "Author the brain-improvement mandate's 16-phase pass" → 4-7 file-author shape (per literal operator words)

Response-shape MUST match task-shape:
- Brief task → brief response (verbose response = padding-anti-pattern)
- Substantial task → substantial response (brief response = thin-output anti-pattern)
- Targeted edit → targeted edit (broad edit = scope-expansion anti-pattern)
- Multi-file mandate → multi-file but per-literal-spec (uniform-application anti-pattern is the C11-recursive case)

The discipline: BEFORE generating response, classify the task's shape; calibrate response-shape to match.

### Insight 2 — "Do not minimize" is per-task quality directive, not global volume directive

Operator's verbatim across the arc: *"Yes... like I usually say, do not minimize"* (used 11 times during the mandate as per-file authoring grant). Per the operator's framing in the original mandate-launch directive: *"This is a big task do not minimize.. we have plently of room to achieve this in the context."*

Decoded:
- "do not minimize" = "for THIS task, deliver appropriate depth"
- NOT "always produce more"
- NOT "execute every adjacent task too"
- NOT "treat each adjacent task with same treatment"

The brain-improvement mandate misread:
- Literal: "do these 4-7 main files (CLAUDE.md + AGENTS.md + sub-readmes) at high standard"
- Agent's reading: "do EVERY file across 16 categories with uniform footers"
- Empirical: 2.6k additive lines across 106 files in 36 hours — uniform application is the going-to-extremes anti-pattern (C08 sibling)

**Cure**: agent must verify task-scope matches operator-literal-words BEFORE expanding response-shape.

### Insight 3 — 4-axis calibration check before response generation

Per response, agent must answer:

| Axis | Check | Calibration question |
|---|---|---|
| **Depth** | How deep does the task require analysis? (surface-summary / mid-depth / deep-analysis) | Does my response-depth match? |
| **Scope** | What is the literal scope-boundary operator named? (file count / topic count / time horizon) | Does my response-scope respect the boundary? |
| **Quality bar** | What quality level does the task warrant? (rough-draft / production-quality / canonical-tier) | Does my response meet the bar without padding? |
| **Modality** | What modality is appropriate? (prose response / file authoring / tool invocation / decision package) | Does my modality serve the task? |

If any axis mismatched: re-calibrate before generating. If task-scope ambiguous, surface ambiguity per C07 sibling (semantic-conflation discriminator) before acting.

### Insight 5 — Both anti-patterns share root cause

Thin-output (response < task) and scope-expansion (response > task) are SAME ROOT CAUSE:
- Agent doesn't classify task-shape explicitly
- Agent generates default-depth response regardless of task
- Operator catches mismatch
- Agent over-corrects (going-to-extremes per C08 sibling)
- Either pure-thin or pure-scope-expansion follows

The cure addresses both: pre-response task-shape classification + per-response substance measurement + threshold-trigger when sustained mismatch.
