## Anti-patterns at master-index layer

| Anti-pattern | Why bad | Closes-gap-via |
|---|---|---|
| Single-axis index only (e.g., chronological by Fire #) | Operator can't find by intent | 4-axis multi-dimensional index |
| Index becomes stale as new pieces added | Operator-empirical state mismatches reality | Index maintenance protocol (update per ≥10-piece additions) |
| Index lacks recall-paths (operator must guess) | Slow lookup | 5+ named recall-paths for common intents |
| Index doesn't surface piece-type taxonomy | Lessons + patterns + logs blur | Axis 3 piece-type index |
| Index doesn't surface tier-maturity | Operator can't filter by promotion-readiness | Axis 4 maturity-tier index |

## When To Apply

Apply this master-index when:
- Body of work has ≥40 pieces (single-axis becomes insufficient)
- Operator + sister-projects need single-jump lookup
- Multi-axis intent (phase × cluster × type) is common
- Maturity tier filtering is operationally relevant
- Pain-point cluster overlap with cross-axis lookup needs

**Instance 3: operator wants to understand architecture quickly**:
- Recall-path: "I want to understand the architecture"

- Operator gets oriented in ~30 minutes (vs scanning 76 pieces ad-hoc)

**Instance 4: future agent wants tier-2-ready pieces**:
- Lookup: Tier 2 — currently 0 pieces (pre-promotion)
- Future state: Tier 2 has N promoted pieces
- Index updates per piece-promotion ceremony

## When Not To

- Body of work <30 pieces (linear pedagogical surface sufficient)
- Single-intent-per-session (no multi-axis lookup needed)
- Cold-start (no body to index)
- Operator-explicit deferral (per-piece linear review preferred)
- Sister-projects without MCP capability (linear reading only)
