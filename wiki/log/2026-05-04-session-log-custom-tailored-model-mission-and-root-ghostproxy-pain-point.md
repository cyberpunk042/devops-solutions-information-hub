## Pain-Point Root-Cause Analysis (the operator's own discipline applied)

Operator's standing directive *"fix it at the root instead.. its not hard"* (CLAUDE.md sacrosanct) applied to the AI alignment overhead pain:

| Layer | What's there | Why repeated alignment overhead persists |
|---|---|---|
| **System** | Debian 13 non-GUI, system-level config | One-time per-machine; not the per-session symptom |
| **Project** | CLAUDE.md, AGENTS.md, .claude/rules/, wiki content | Fully configured; loaded each session — but each load pays alignment cost |
| **Harness** | Claude Code / OpenCode / Codex configuration | Operator-authored; per-harness; correct posture |
| **Ecosystem** | Multica · AICP routing · sister-project profiles | Configured; per-session retraversed for routing decisions |
| **Model weights** | Frontier model (Opus 4.x) trained on broad corpus | **The root** — model's bimodal training (newbie + senior) compromises both modes; alignment must be re-applied per session via prompting because the model's *prior* is general, not operator-tier |

The *root cause*: alignment substrate is external to the model. The *root solution*: bake operator's standards into the weights — preference fine-tune + curated instruction data + behavioral constitution — so the model's *prior* IS operator-tier. CLAUDE.md + .claude/rules/ + per-project config remain the per-project specialization layer; but the cross-project behavioral floor (do-things-right-by-default · senior-engineer-tier · methodology-first) sits in the weights, not in repeated runtime prompting.
