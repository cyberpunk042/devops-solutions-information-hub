## Why the failure happened despite impl-spec #10 existing (gap analysis)

This is the substitution-pattern (per `wiki/lessons/01_drafts/documentation-as-substitute-for-discipline-the-meta-pattern.md`) at the IMPLEMENTATION-PATTERN layer:

1. **Documentation existed**: impl-spec #10 (~Fire 50) describes the bidirectional design comprehensively
2. **Implementation did NOT fully exist**: only PostCompact side wired; PreCompact hook never authored
3. **The body of work proceeded as if implementation followed documentation**: 50+ subsequent fires referenced impl-spec #10 as if both sides operational
4. **Real-session stress-test exposed the gap**: this incident is the FIRST event where impl-spec #10 was actually exercised AND failed

This is structurally identical to:
- Hard Rule 1 in CLAUDE.md (read output in full) — documented since session-start; agent still defaults to truncation under pressure (closed by pre-bash.sh hook 2026-05-04)
- SB-095 hallucinated-artifacts (closes via "agent-DRAFT" frontmatter; pattern recurred during the mandate window)
- Brain-improvement mandate (36+ hours of /root authoring with ZERO `gateway orient` invocations despite the brain prescribing it)

The lesson at meta-level: **a body-of-work that documents its own discipline patterns proves the patterns by EXERCISING them in real-session, not by adding more documentation about them**. Fire 102 (this piece) IS the exercise — converting the failure into persistent intelligence per the 10-verb workflow (aggregate → process → evaluate → learn → integrate → modelize → validate → standardize → teach → offer).
