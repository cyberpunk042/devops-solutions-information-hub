- "PROFILES... PROFILES... NOT PROFILE"
- A project has MULTIPLE Profiles, NOT one
- Each Profile = one specific focused assistant job
- Multiple Profiles can run CONCURRENTLY (e.g., two 24/7 for the second-brain on the same computer + one for root-ghostproxy)

### B — Operator's named example Profiles (sacrosanct)
- **"Continuous Research"** = *"Do research to make sure the models are up to date and our vision of the technogies are still acquire, and we do the proper update and etc..."*
- **"Synthesize the ingested information still not at the end of the pipeline"**
- "Things like this..." → more Profiles may exist beyond these two; operator-namable

### C — Drift / corruption correction (recurring family)
- "Return read what I said... stop conflating and reshaping the idea... I AM THE ONE DEFINING IT"
- Same family as the prior corrections (D15 corrupt-Profile-as-tool-config; M006-cross-project-violation; etc.)

- The fix: ABSORB, don't reshape. Operator defines the concept; I implement within their definition.

### D — Urgency + usability target
- "REMEMBER WHAT THE TRACKS ARE... PROFILES ASAP"
- "SO I CAN RUN FOR EXAMPLE AT LEAST ONE AGENT OPENCLAW 24/7 FOR THIS PROJECT HERE, THE SECOND-BRAIN"
- The operator wants USABLE Profiles ASAP — at least ONE Profile ready to be consumed by an OpenClaw 24/7 agent for the second-brain
- "AT LEAST ONE" implies more is welcome; bare minimum is one
- Profiles must be useful, not just well-documented

### E — Cross-tool management requirement (re-emphasized)
- "AND THE MANAGING ACCROS NONE, ONE OR MULTIPLE TOOL LIKE I SAID"
- A Profile can be:
  - Consumed by NONE (a definition without a current instance)
  - Consumed by ONE tool (one instance, e.g., one OpenClaw agent)
  - Consumed by MULTIPLE tools (e.g., same Profile spawned on OpenClaw + Multica simultaneously)
- The Profile remains stable across consumer count + composition
